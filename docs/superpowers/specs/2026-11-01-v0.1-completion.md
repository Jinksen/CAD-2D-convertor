# v0.1 completion — spec

Date: 2026-11-01 · Branch: `feature/v0.1-completion` · Follows `2026-11-01-ux-performance.md`

## Goal

Close the remaining gaps between the app and the v0.1 acceptance criteria in
`CAD2Maxwell_PROJECT_SPEC.md` (§47): bounded backend memory, fast sections on large
assemblies, project save/load, diagnostics linked to geometry, visibility control,
spec-conformant shortcuts, themes, and a reproducible demo model for docs and tests.

## Non-goals

- No change to exact sectioning results, wire classification or DXF geometry.
- No new runtime dependencies.
- No installer/bundled Python backend (release stays "build from source").

## Constraints

CLAUDE.md and AGENTS.md apply: exact B-Rep only, typed DTOs, no OCC objects in the frontend,
no silent repair, ASCII export names, every behaviour change tested, `scripts/test.ps1` green.
`frontend/src/features/step-import/StepImportWorkspace.tsx` was split before this pass into
`ModelTree.tsx`, `ModelSettings.tsx`, `MessagesPane.tsx`, `useGlobalShortcuts.ts`, `color.ts`.

### T14 — Bounded sessions
`ImportSessions`, `SectionSessions` and the preview cache never evict; automatic recompute
creates a new section per edit. Acceptance: keep the most recent 3 imports and 32 sections
(LRU, constants in one place); evicting an import also drops its sections and preview; an
evicted id returns the existing 404 codes and the UI shows its existing "Import again" message.
Test: eviction order, cascading removal, 404 after eviction.

### T15 — Bounding-box prefilter
`SectionService.create` runs `BRepAlgoAPI_Section` for every body. Acceptance: bodies whose
exact bounding box (with the tolerance from `TolerancePolicy`) lies entirely on one side of the
plane are skipped; results are identical to the unfiltered run. Test: result equality on the
fixtures, and a counter/spy proving skipped bodies are not sectioned.

### T16 — Section cache
Acceptance: identical requests (same import, plane kind, normal, offset within tolerance)
return the cached `SectionResponse` (same `section_id`) without recomputing; any plane change
misses the cache; cache entries obey T14 eviction. Test: hit, miss, eviction.

### T17 — Small regions and slivers
Tiny edges are already reported (`tiny_section_edge`). Acceptance: closed regions with area
below a `TolerancePolicy` threshold, or slivers (area / perimeter² below a threshold), produce a
`warning` diagnostic naming the body; nothing is removed or repaired. Test: synthetic thin
rectangle and tiny square.

### T18 — STEP reader diagnostics
"OpenCascade reported 9 STEP reader failure(s)." is an `error` even when bodies imported.
Acceptance: severity `warning` when at least one body imported (`error` when none); the message
lists up to 5 distinct reader messages with counts, ASCII-safe. Test: partial-failure fixture.

### T19 — Project file
Spec §10. Acceptance: `.c2mproj` (JSON, versioned, ASCII keys) stores the STEP path and
SHA-256, plane kind/normal/offset, number format, visibility state and per-body user overrides
that exist; Ctrl+S save, Ctrl+Shift+S save as (native dialogs via Tauri commands; browser dev
fallback = download), Open accepts `.c2mproj` and re-imports the STEP; a hash mismatch is a
clear warning, never silent; unknown future versions are rejected with a message. No CAD
geometry inside the project file. Tests: round trip, hash mismatch, version rejection.

### T20 — Undo/redo
Spec §42. Acceptance: plane kind, normal and offset edits are undoable (Ctrl+Z / Ctrl+Y,
also Ctrl+Shift+Z) as user-level commands in frontend state, debounced so typing one value is
one step; history clears on new import. Test: store-level undo/redo sequence.

### T21 — Diagnostics linked to geometry
Acceptance: clicking a section diagnostic with `component_id` selects that body, switches to
2D and fits the view to it (related body also highlighted for overlaps); messages and the status
bar show ✓ PASS / ⚠ WARNING / ✕ ERROR with text, not colour alone (spec §44). Ctrl+L focuses
the Messages pane. Test: click → selection and view change.

### T22 — Visibility and isolate
Acceptance: eye toggle per body in the Model Builder; V toggles the selected body, I isolates
it (I again restores all); hidden bodies disappear in 3D and are drawn as faint outlines in 2D;
visibility never changes sectioning or export. Test: store + component tests.

### T23 — Fit and viewport polish
Acceptance: F fits the selected body (fallback: all), Shift+F fits all, in whichever of 2D/3D is
visible (global, not only when the canvas is focused); the 3D plane guide no longer covers the
model (depth-tested surface, edges on top); "No messages." is not shown while an operation is
running; add a favicon. Tests for fit selection maths and the messages state.

### T24 — Shortcuts per spec §41
Acceptance: 1 / 2 / 3 select the XY / XZ / YZ plane (replacing 2D/3D on 1/2); Ctrl+1 / Ctrl+2
switch 2D / 3D; Ctrl+O, Ctrl+Enter, Ctrl+E, Esc keep working; tooltips and the README
shortcut table updated. No conflicts with T20/T21/T22/T23 keys. Test: component test.

### T25 — Themes
Spec §43. Acceptance: System (default), Light, Dark selectable in the Units and Number Format
node (rename the node to "Preferences"); colours become CSS custom properties; 2D and 3D canvas
backgrounds, grid and outline colours follow the theme; choice persisted like the number format.
Test: setting persists and sets `data-theme`.

### T26 — CI on pull requests
`.github/workflows/ci.yml` only has `workflow_dispatch`. Acceptance: also runs on `pull_request`
and pushes to `main`, executing `scripts/test.ps1` on `windows-latest`; comment updated. (GitHub
Actions may still need enabling in repository settings — note it in the PR.)

### T27 — Maxwell import checklist
Acceptance: `docs/maxwell-import-checklist.md` — step-by-step manual verification of
acceptance criteria 13–15 (DXF import in Maxwell 2D, separate selectable objects, manifest
mapping), with expected results and a results table to fill in.

### T28 — Demo motor model
Acceptance: `scripts/demo/make_demo_motor.py` (uses the backend venv and OCP) writes a
synthetic, license-free motor STEP: laminated stator with slots, rotor with magnets, shaft and
coil sides, with named, coloured bodies in an assembly. Deterministic output. Used for README
screenshots and as a backend regression fixture (import + XY mid section: expected body count,
region count, no error diagnostics).
